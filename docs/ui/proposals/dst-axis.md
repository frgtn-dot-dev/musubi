# Clock-change axis preparation

Status: isolated model and Storybook proposal; no production caller uses it.

`apps/web/src/calendar/day-axis.ts` takes an explicit IANA timezone and civil
date. It enumerates real minute instants, retaining a civil minute, occurrence
(fold), and UTC offset for each. It does not normalize missing times. A standalone
day has its actual elapsed length: 23/25 hours in Prague and 23.5/24.5 in Lord
Howe. Coordinates support fractional minutes; hit-testing is end-exclusive.
Resize ends have a separate explicit boundary resolver. Skipped dates, invalid
zones/dates, non-contiguous dates and historical sub-minute offsets are refused.
This prototype scans a bounded UTC window; production should memoize a bounded
visible range rather than rebuild axes on every render. It stores no user data.

The week union preserves chronological order within each day and aligns ordinary
civil times across columns. On a fall-back week, the repeated block is inserted
as a complete block; other dates have no instant in those rows. On a spring week,
the transition date has holes where adjacent dates have real times. Missing rows
are not clickable, focusable, or drop targets. A continuous real interval can
produce multiple visual segments around a hole; adding segment heights still
equals elapsed duration. No event identity is generated by this model.

## Concrete visual decision to review

Storybook: **Calendar / Clock-change axis proposal**, five variants: Prague
spring/fall, Lord Howe spring/fall, and normal day. Each shows both day and week.
Existing section, row and button primitives provide the surrounding composition;
quiet grid rules, type and surfaces use existing tokens. The week scrolls
horizontally on a narrow viewport; its timeline remains vertically scrollable.

The proposed production pattern is **shared civil rows with reserved missing
rows**, labelled “No local time”, and repeated ticks labelled with UTC offset
plus “first”/“second”. Approving this pattern chooses aligned civil hours across
a mixed-length week rather than aligning elapsed minutes since each midnight.
Standalone days omit nonexistent rows and show both real repeated occurrences.
The screenshot is a geometry/label demonstration, not a production restyle or an
approved event renderer. Production adoption of the missing-row treatment and
repeated-label anatomy waits for review of this concrete Storybook variant under
`.agents/skills/musubi-ui/SKILL.md`; the pure correctness work is implementable
without a live account or provider approval.

## Remaining production handoff

- Replace the independent time calculations in `TimeGridView.tsx`,
  `time-grid-math.ts`, `time-geometry.ts`, `time-grid-drag.ts` and
  `use-time-grid-drag.ts` with the same axis for ticks, now, initial scroll,
  segmentation, hit-testing, draft preview, mouse/touch drag and keyboard moves.
  Keep normal-day geometry, overlap placement and event access unchanged.
- Pass exact start/end instants through Workspace, compact/full editor handoff
  and drag commits. An HH:MM string alone loses the second repeated occurrence;
  untouched dates/times must retain the chosen instant. An explicit edit to a
  civil time must resolve its possible instants or report a gap, never silently
  rely on `Date#setHours` normalization. Move keeps real duration; resize computes
  duration from its fixed instant and target boundary. A drop into a missing row
  is invalid and retains the previous draft; do not invent a snapping policy.
- Render cross-hole intervals as linked visual segments of their existing event,
  with one coherent action/focus identity. The renderer must not accidentally
  make one visual segment resize the wrong edge. This interaction integration is
  outstanding; the proposal intentionally contains no fabricated events.
- Keep shared calendar layout/native callers unchanged until their own mapping
  is migrated. The existing `layout/day-segments.ts` elapsed-minute contract can
  remain a source of clipped instants; a web-specific axis projection follows it.
- Once grid intervals use this same tested projection, remove the availability
  DST exclusion. Preserve selection/query fences and interval-only semantics.

Production acceptance must assert the exact UTC create/move/resize payload for
both Prague repeated 02:30 occurrences, refused spring 02:30, Lord Howe 30-minute
changes, cross-midnight intervals, and a week with differently sized days.
Browser tests must verify selection/preview geometry agrees with saved payload,
keyboard and pointer reach both folds, invalid drop preserves the draft, resize
can reach day end, and focus returns correctly. Add narrow/light/dark coverage
and offscreen scrolling. Those production interaction claims are not made by
this model or Storybook preparation batch.
