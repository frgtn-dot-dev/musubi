# Outlook occurrence rescheduling — 2026-09-22

A stored occurrence of a verified finite UTC Outlook series can change its start and end in the existing web/native editor. This covers personal events and meetings organized by the connected account in its default calendar, including already moved exceptions and both provider-expanded and canonical imports. The original occurrence identity, other slots, content, guest responses and cancellations must survive.

This stage supports timed UTC series only. Both `PROVIDER_ORGANIZER_EDITS_ENABLED` and `EVENT_TIME_EDITS_ENABLED` are required. Other authoring zones, all-day changes, whole-series time, recurrence changes and “this and following” remain unsupported. Existing complete-family limits (366 slots / 730 days), identity, ownership, attachments and online-meeting restrictions still apply. No flags, migration, dependencies, release or deployment are changed by this work.

## Contract

- Clients opt in with `outlookOrganizer=5`; v1–v4 keep their prior response and editing behavior. The separate series-content capability remains content-only. Time is advertised only after the complete native family and selected stored mapping qualify.
- A strict occurrence request carries the existing revision, provider-state version and full family proof plus one complete explicit UTC time value. One-off and series time payloads, all-day, floating and non-UTC times are rejected. Admission checks the existing flag and neighbouring days, including cancelled slots and moved neighbours. A definitively rejected admission allows editing the draft again.
- Microsoft documents that an occurrence cannot cross onto the previous or following occurrence's day ([event update](https://learn.microsoft.com/en-us/graph/api/event-update?view=graph-rest-1.0)). Musubi conservatively checks both start/end against original and current neighbours before writing. A native `400 ErrorOccurrenceCrossingBoundary`, like 412, is a definite rejection that releases the pending operation fence. Other ambiguous outcomes retain the fence.
- The existing private journal and calendar import fences are retained. Full local/native baselines are rechecked before a permanent dispatch marker and one conditional instance PATCH. Only start/end and any explicitly edited content are sent; no guest, recurrence, original-slot or master mutation is sent.
- Durable native acceptance plus full-family and full-target readback is required before the local time commits. UTC fractional precision is normalized only for comparing the changed endpoints. Guest responses and all other native fields are still compared. A matching recovered read never resends the PATCH; missing acceptance or drift remains unconfirmed. Bounded read-only retries accommodate Graph propagation.
- Completion changes only the selected local event's explicit UTC time and revision, while refreshing verified family mappings. It preserves local series identity and original start. Content-only operations keep their previous local time behavior.
- Web and native reuse the existing date/time controls. All-day and zone conversion stay disabled. Personal events use Save; meetings use the existing notification action. Network retry preserves the entire request and operation ID.
